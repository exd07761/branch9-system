v1.1 Migration Dry Run

IM-4 (IMPLEMENTATION_ROADMAP.md) — reads a Backup & Restore export file and reports how existing Hearings/Cases would reconstruct into the new Case entity, without writing anything anywhere. Not part of the Clerk-facing application and not linked from anywhere in it — same kind of standalone developer tool as diagnostics.html.

This is an analysis-only tool. It performs no migration of any kind, makes no Firestore calls of any kind (not a single read), and exists solely to generate evidence for the IM-5 Business Validation Checkpoint. There is nothing on this page that writes, migrates, or modifies anything, anywhere.

What this does — and does not — do

  • Reads a .json file you choose from your own computer, entirely in this browser tab. Nothing is uploaded anywhere.
  • Never connects to Firestore. Never writes anything, anywhere — not to production, not to a staging project, not to this file. There is no "run migration" button on this page, on purpose.
  • Produces evidence to help resolve the still-Pending Business Validation Checkpoint (IM-5) — Decisions 009, 015, 016, 017, and 018 in IMPLEMENTATION_READY.md — with real data from your own records, and to surface anything that won't reconstruct cleanly before any real migration (IM-7) is designed. That is the sole purpose of this page.
  • Use a real Backup & Restore export (backup.html) as the input file — it already contains hearings and hearingCases in the shape this tool expects.
